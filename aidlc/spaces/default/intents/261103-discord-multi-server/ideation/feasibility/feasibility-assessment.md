# Feasibility Assessment

対象の意図: `aidlc/spaces/default/intents/261103-discord-multi-server/ideation/intent-capture/intent-statement.md`（intent-statement）

## 結論

**条件付きで実現できます。** 別の Discord サーバー向けに完全に分離したサーバーを 1 つ追加することも、サーバーごとにオペレーター権限を付与することも、今の構成の延長で実現できる見込みです。

条件は次の 3 点です。

1. 今の仕組みには「サーバーは 1 台だけ」という前提が残っているため、**新しいサーバーを作る前に**、その前提を取り除く必要があります。順序を誤ると、今のサーバーの起動や停止が失敗します。
2. 月額の合計は約 4,450〜5,000 円の見込みで、今の予算（月 3,000 円）を超えます。予算の見直しが必要です。
3. 新しいサーバーの通知先には、向こうの主催者や管理者に作ってもらう Discord の webhook が必要です。

## 実現性の根拠

| 観点 | 判定 | 根拠 |
|---|---|---|
| リソースの分離 | 実現できる | `modules/` のモジュールは接頭辞（prefix）で名前を分けられます。ネットワーク、ワールド、バックアップ、通知先の秘匿パラメータも接頭辞ごとに分かれます |
| 起動・停止・復元の分離 | 変更が必要 | `scripts/cd/common.py` の `instance_id()` は、アカウント内の管理対象サーバーが 1 台だけであることを要求します |
| CI/CD の分離 | 変更が必要 | CI、CD、手元のスクリプトが `envs/prod` を前提にしており、`bootstrap/iam.tf` の OIDC も環境 `prod` と `ops` に固定されています |
| 監視の分離 | 変更が必要 | 一部のカスタムメトリクスにサーバーを区別する情報がなく、2 台の値が混ざります |
| オペレーター権限 | 実現できる | サーバーのコンテナイメージ（`itzg/minecraft-server`）は `OPS` 環境変数に対応しています。ホワイトリストと同じ仕組みで渡せます |
| 既存サーバーへの影響 | 管理できる | 誰も遊んでいない時間であれば、停止してよいと回答いただいています（Q4） |

## 検討した方式

| 方式 | 内容 | 分離の強さ | 評価 |
|---|---|---|---|
| A. 同じ AWS アカウントで接頭辞を分ける | サーバー機、ワールド、通知、起動・停止を別々に持つ | 高い | **推奨**。デプロイ先のアカウントを `personal` とする既存のルールに沿います |
| B. 別の AWS アカウントを使う | アカウントごと分ける | 最も高い | 見送り。既存のルールの変更が必要で、管理の手間も増えます |
| C. 同じサーバー機に相乗りする | 1 台で 2 つのサーバーを動かす | 低い | 見送り。すべて別々にするという回答（Intent Capture の Q3）に合いません |

具体的な構成は Infrastructure Design で決めます。

## 費用の見積もり

金額は過去の見積もりをもとにした 2026 年時点の概算で、1 USD = 150 円で換算しています。実際の金額は要確認です。

| 項目 | 今のサーバー（月 40 時間） | 新しいサーバー（月 20 時間、16 GB） |
|---|---|---|
| EC2 | 約 1,260 円 | 約 630 円 |
| 固定 IP（停止中も課金） | 約 550 円 | 約 550 円 |
| ディスク（EBS） | 約 550 円 | 約 550 円 |
| バックアップ（S3） | 約 120〜270 円 | 約 120〜270 円 |
| CloudWatch、Lambda など | 約 62〜187 円 | 約 62〜187 円 |
| **合計** | **約 2,540〜2,820 円** | **約 1,910〜2,190 円** |

- 2 台の合計は**約 4,450〜5,000 円**です。新しいサーバーも月 40 時間稼働すると、約 5,100〜5,650 円になります。
- 遊ばない月でも、新しいサーバーには約 1,200〜1,400 円かかります。
- 今と同じ性能で許容すると回答いただいています（Q2）。新しいサーバーの稼働は月 20 時間以下の想定です（Q1）。

## オペレーター権限の扱い

- ユーザー名は、ホワイトリストと同じ秘匿パラメータに置きます（Q5）。公開リポジトリには名前を出しません。
- 変更は手元で行い、次の起動で反映します。仕組みの追加そのものは、PR とデプロイで反映します。
- Intent Capture の Q8 では「PR とデプロイで反映する」と回答いただきましたが、名前の置き場所を確認した結果、この Q5 の回答を優先します。
- 取り消しも確実に反映するには、イメージの既定の動作を変える設定が必要です。既定では、`OPS` の名前を既存の一覧に追加するだけで、削除された名前が残る可能性があります（[公式ドキュメント](https://docker-minecraft-server.readthedocs.io/en/latest/configuration/server-properties/)からの推測で、実機での確認が必要です）。

## 残る未確認事項

- 実費の分担を受け取ること（Q6）が Minecraft の利用規約に沿うかは、確認できていません。公式ページの取得が 2 回ともタイムアウトしたため、利用者から受け取る前にご本人の確認が必要です（`raid-log.md` の I1）。
- 費用はすべて概算です。AWS の料金ページとの照合は行っていません。
