# Intent Statement

## Problem Statement

別のコミュニティ向けに、今とは別のワールドの Minecraft サーバーを用意したいと考えています。 [desc] [Q1]

新しいサーバーは今のサーバーから完全に分離し、ワールド、バックアップ、通知、起動・停止、バージョン・MOD のいずれも互いに影響しないようにする必要があります。 [Q3]

あわせて、指定した人にゲーム内のオペレーター権限（`/gamemode`、`/kick` などのコマンドを使える権限）を付与できるようにしたいと考えています。 [desc] [Q5]

## Target Customer

- 別の Discord サーバーのコミュニティのメンバーが、新しいサーバーの利用者です。 [Q1] [Q2]
- サーバーの構築と運用を担当するご本人は、管理者権限を設定で管理できるようになります。 [Q2] [Q8]

## Success Metrics

次の 3 点をすべて確認できたら完了とします。 [Q6]

- 新しいサーバーに Minecraft クライアントから接続でき、通知が対象の Discord にだけ届くこと。 [Q6]
- 新しいサーバーを起動・停止・更新・復元しても、今のサーバーとワールドに影響しないこと。 [Q6]
- 指定した人が管理者権限を持ち、対象外の人は持たないことをゲーム内で確認できること。 [Q6]

## Initiative Trigger

今とは別のコミュニティ向けにサーバーを用意したいことがきっかけです。 [Q1]

期限はなく、準備ができたら始めます。 [Q9]

## Initial Scope Signal

- 作業の進め方: `workflow-selected` `bugfix` をベースにしたカスタムプラン。 [scope]
- 今回追加するサーバーは 1 つで、今のサーバーと合わせて 2 つになります。 [Q4]
- 管理者権限が指すのはゲーム内のオペレーター権限です。 [Q5]
- オペレーター権限は今のサーバーと新しいサーバーの両方で、サーバーごとに指定します。 [Q12]
- 今回オペレーター権限を付与するのはご本人だけで、Minecraft のユーザー名で指定します。 [Q13]
- サーバーをすべて別々にすることで増える費用は、Feasibility の見積もりを見て、進めるかどうかを判断します。 [Q14]
- テストは、チームの基準（全モジュールに plan モードの `terraform test`、必須チェックの通過）に加え、追加する動作についても書きます。 [Q15]
- 管理者権限は、ご本人が設定を変更し、PR とデプロイを経て反映します。すぐに反映できなくても構いません。 [Q8]
- 新しいサーバーは新しいワールドから始め、今のワールドは引き継ぎません。 [Q7]
- Discord から操作する機能は、今回は追加しません。 [Q7]
